3. **P0 — Navegadores integrados:** una investigación del 29/10 encontró lecturas de archivos fuera del ámbito esperado en Codex, VS Code y Claude Desktop. Según los investigadores, Codex y VS Code no tenían parche en la fecha de publicación; no se ha verificado una corrección posterior.

## Novedades prioritarias

### 1. P0 · Extensión Claude Code maliciosa en el marketplace de Cursor

**Qué cambió — 29/10/2026.** Cursor confirmó que su marketplace distribuyó builds modificadas de `anthropic.claude-code` **2.1.312 y 2.1.313** para macOS y Windows durante unas once horas. El código intentaba añadir una clave SSH, establecer persistencia y abrir un túnel inverso. Cursor retiró los paquetes, reconstruyó el marketplace y desconectó el servidor atacante. Según el proveedor, el acceso remoto normalmente fallaba por falta de privilegios, pero podían quedar modificaciones locales.

**Por qué importa.** Una extensión ejecuta código en un equipo con acceso potencial a tokens, repositorios y credenciales. El riesgo depende del marketplace y la versión instalados, no de utilizar Claude Code en general.

**Hacer:** inventariar versiones y origen de instalación; buscar los indicadores publicados. Si hay coincidencias, aislar el equipo, conservar evidencias, aplicar la remediación oficial y rotar credenciales accesibles desde un entorno limpio. **Desinstalar la extensión no basta** si ya se instaló persistencia.

**Ignorar:** afirmar que todas las extensiones oficiales de Claude están comprometidas.

**Fuente:** [aviso oficial de Cursor e indicadores de compromiso](https://cursor.com/blog/claude-code-extension-security-notice).

### 2. P0 · Hono 4.13.16: controles HTTP que podían omitirse

**Qué cambió — estable, 01/11/2026.** La release corrige cinco problemas:

- `mount()`/`app.mount()` podían reenviar rutas manipuladas que eludían middleware limitado al prefijo.
- `RegExpRouter`, utilizado por `SmartRouter`, podía omitir middleware wildcard con ciertos patrones y rutas codificadas.
- `validator('form')` no reconocía algunos `multipart/form-data` con parámetros adicionales.
- `css` podía permitir inyección HTML mediante cierres de `style` repartidos entre segmentos.
- `csrf()` no comprobaba POST de auditoría de enlaces con `text/ping`.

**Por qué importa.** Un test de la ruta feliz no demuestra que todas las variantes pasen por autenticación y validación. Hay además patrones de ruta que ahora pueden lanzar error; si se utiliza `PreparedRegExpRouter`, deben regenerarse sus datos.

**Hacer:** ejecutar `pnpm why hono`; si está instalado, actualizar a **4.13.16+** y añadir regresiones negativas sobre rutas montadas, comodines, formularios y CSRF. Comprobar que las peticiones rechazadas nunca alcanzan el handler protegido.

**Ignorar:** refactorizar el backend completo por un parche focalizado.

**Fuente:** [release oficial Hono 4.13.16](https://github.com/honojs/hono/releases/tag/v4.13.16).

### 3. P0 · EMBRACE: los navegadores de agentes no son un límite de seguridad fiable

**Qué cambió — investigación publicada el 29/10/2026.** Forever Security demostró problemas **diferentes** en los navegadores integrados de Cursor, Copilot, Codex, VS Code y Claude Desktop. Para los tres últimos documentó lecturas de archivos locales fuera del directorio previsto después de abrir HTML local; VS Code y Claude Desktop involucraban web workers. En Cursor mostró una vía de ejecución mediada por instrucciones al agente; en Copilot, suplantación de dirección. Los investigadores indicaron que Cursor y Copilot estaban corregidos y que Codex y VS Code seguían sin parche en la fecha del informe. La situación exacta de Claude Desktop no queda delimitada.

**Por qué importa.** Un HTML local o una página externa puede aprovechar permisos añadidos al navegador integrado. No equivale a decir que abrir cualquier repositorio ejecute el ataque: la demostración de lectura requería abrir un archivo mediante un enlace.

**Hacer:** evitar abrir HTML de proyectos desconocidos en navegadores integrados, revisar Workspace Trust, usar entornos desechables sin secretos para repositorios no confiables y seguir avisos del proveedor. Tratar enlaces propuestos por el agente como entradas no confiables.

**Ignorar:** confundir una investigación con explotación masiva confirmada o afirmar que todos los productos comparten una misma CVE.

**Fuentes:** [Forever Security](https://forever.security/blog/embrace-hacking-5-ai-assistants-embedded-browsers/) · [The Register](https://www.theregister.com/security/2026/10/29/researchers-find-bugs-in-5-ai-developer-tools-with-openai-and-microsoft-flaws-still-unpatched/5306508).

### 4. P1 · Node 26.13.0 ya es LTS

**Qué cambió — estable, 28/10/2026.** Node **26.13.0 «Lithium»** inicia su etapa LTS, con soporte anunciado hasta abril de 2029. Node **24.22.2** continúa soportado. La transición de 26.12.1 a 26.13.0 modifica principalmente metadatos de soporte, no introduce una gran funcionalidad.

**Por qué importa.** El runtime afecta a Vite, Vitest, pnpm, scripts, imágenes Docker y módulos nativos. Los binarios Linux desde Node 25 pueden necesitar `libatomic`.

**Hacer:** mantener Node 24 parcheado y añadir Node 26 como job no bloqueante. Probar instalación limpia, build, tests, imágenes y dependencias nativas. Convertirlo en baseline solo tras validar compatibilidad y costes de CI.

**Ignorar:** migrar inmediatamente todos los repositorios solo porque 26 haya alcanzado LTS.

**Fuentes:** [Node 26.13.0](https://github.com/nodejs/node/releases/tag/v26.13.0) · [Node 24.22.2](https://github.com/nodejs/node/releases/tag/v24.22.2).

### 5. P1 · pnpm 12.17.0 mejora instalaciones repetibles

**Qué cambió — estable, 30/10/2026.** pnpm **12.17.0** incorpora selectores por grupo y comodines en `overrides`, mejora la gestión de versiones de runtimes y corrige permisos de archivos generados en Docker, enlaces de dependencias locales, detección de cambios en workspaces y falsos fallos con `--frozen-lockfile`. La rama 11 recibió la corrección de mantenimiento **11.28.10**.

**Por qué importa.** Algunos de estos errores hacen que una instalación parezca correcta y luego falle al ejecutar con otro usuario o tras modificar una dependencia local.

**Hacer:** si se usa pnpm 12, evaluar el patch en una PR: instalación limpia y repetida, lockfile congelado, paquetes `workspace:` y ejecución con usuario no root. Mantener pnpm 11 actualizado dentro de su rama donde todavía se utilice.

**Ignorar:** adoptar nuevas opciones de overrides sin un problema concreto.

**Fuente:** [pnpm 12.17.0](https://github.com/pnpm/pnpm/releases/tag/v12.17.0).

### 6. P1 condicionado · Sentry JavaScript 11.10.0

**Qué cambió — estable, 28/10/2026.** Permite configurar `tunnel: true` en el SDK de navegador y `serveTunnelIntegration()` en servidores compatibles para encaminar eventos por infraestructura propia. El soporte automático incluye Astro, Nuxt y Nitro, **no una SPA estática Vue sin servidor**. También cambian nombres de orígenes de spans, incluidos `auto.http.browser.*` → `auto.ui.browser.*`.

**Por qué importa.** El túnel puede reducir pérdidas de eventos por bloqueadores, pero requiere capacidad y protección del servidor. Las nuevas etiquetas pueden romper filtros `ignoreSpans`, consultas y alertas que dependan de nombres antiguos.

**Hacer:** comprobar major instalada, revisar dashboards y probar el túnel únicamente si existe un problema de entrega medido. Evaluar costes, abuso del endpoint y tasas de recepción.

**Ignorar:** montar un proxy o saltar de major sin necesidad.

**Fuente:** [Sentry 11.10.0](https://github.com/getsentry/sentry-javascript/releases/tag/11.10.0).

### 7. P1 condicionado · TanStack Vue Query y Virtual

**Qué cambió — estables, 01/11/2026.** `@tanstack/vue-query@5.105.1` corrige la sobrecarga de `infiniteQueryOptions` con `initialData` posiblemente indefinido y restringe filtros de `isFetching`. `@tanstack/vue-virtual@3.13.51` elimina observadores de scroll cuando el elemento desaparece; el core corrige el rango visible después de reducir una lista larga.

**Por qué importa.** Son correcciones de tipos y comportamiento que pueden afectar a infinite queries y tablas virtualizadas filtradas.

**Hacer:** actualizar **si se usan** y reproducir los escenarios afectados. En Virtual, filtrar una lista larga mientras se está desplazado cerca del final.

**Ignorar:** iniciar la adopción de TanStack solo por estas patches.

**Fuentes:** [Vue Query](https://github.com/TanStack/query/releases/tag/%40tanstack/vue-query%405.105.1) · [Vue Virtual](https://github.com/TanStack/virtual/releases/tag/%40tanstack/vue-virtual%403.13.51).

## Deep dive · Límite de confianza para agentes de desarrollo

Los incidentes de esta semana no son idénticos: uno es un compromiso de distribución y otro, un aislamiento insuficiente del navegador. Ambos cuestionan la idea de que una herramienta integrada en el editor es automáticamente confiable.

**Propuesta para el equipo:** tratar README, tickets, HTML, logs y respuestas MCP como **datos no confiables**; ejecutar cambios autónomos en worktrees y runners efímeros; no exponer secretos de producción; restringir red y permisos cuando sea viable; exigir tests y revisión humana antes de merge. Guardar evidencia de ticket, commit, comandos ejecutados y checks.

**Ventajas:** menor impacto potencial de contenido hostil y mayor reproducibilidad. **Costes:** preparar contenedores, semillas y permisos lleva trabajo; un sandbox mal configurado puede bloquear tareas o transmitir falsa seguridad.

**Decisión:** empezar por un flujo aislado en un único repositorio, sin secretos y con datos ficticios. No solucionar la fricción de permisos activando modos de ejecución sin restricciones.

## Radar de herramientas y prácticas

**1. [oasdiff](https://www.oasdiff.com/docs/getting-started) — OpenAPI breaking changes.** Detecta incompatibilidades entre especificaciones antes de merge mediante `oasdiff breaking`; dispone de CLI y GitHub Action. **Ventaja:** independiente de .NET/Hono/Vue. **Límite:** no verifica que la implementación respete OpenAPI; necesita contratos actualizados. **Madurez:** herramienta OSS estable, con revisión comercial opcional. **Alternativas:** OpenAPI Diff, Pact. **Piloto:** añadir un campo obligatorio a una petición y comprobar que CI lo rechaza.

**2. [Testcontainers para .NET + SQL Server](https://dotnet.testcontainers.org/modules/mssql/) — datos repetibles.** Levanta una base aislada, aplica scripts de escenario y la destruye tras el test. **Ventaja:** evita depender del estado de QA compartido. **Límites:** requiere Docker, recursos, licencias apropiadas y migraciones/semillas; no convierte automáticamente un backend .NET Framework legacy en containerizable. **Madurez:** módulo oficial establecido. **Alternativas:** docker-compose y bases con snapshots. **Piloto:** ejecutar dos veces una prueba de integración con la misma semilla.

## Experimento recomendado (25 minutos)

**Objetivo:** impedir un breaking change accidental de OpenAPI.

1. Elegir dos especificaciones válidas, sin datos sensibles (5 min).
2. Cambiar una propiedad opcional a obligatoria (5 min).
3. Ejecutar `oasdiff breaking --fail-on ERR base.yaml revision.yaml` (5 min).
4. Comprobar el error, revertir el cambio y repetir (5 min).
5. Decidir dónde integrar el check y cómo documentar excepciones (5 min).

**Éxito:** el cambio incompatible falla, el compatible pasa y el resultado identifica endpoint y propiedad. El análisis se ejecuta localmente sin subir contratos privados.
