# Actualizar contenido publicado

Leer `docs/editorial-workflow.md` y el artículo original. Aplicar
`.agents/skills/research-sources/SKILL.md` para los hechos cambiantes.

1. Identificar qué afirmación, ejemplo o enlace ha quedado obsoleto y a quién
   afecta. No actualizar por cambiar palabras o por una versión sin consecuencias.
2. Contrastar el comportamiento vigente con fuentes primarias y ejecutar ejemplos
   afectados cuando sea viable. Respetar el contexto histórico del artículo.
3. Editar solo las secciones necesarias. Conservar nombre de archivo/URL, `date`,
   issue y posición de serie. Para un cambio sustancial, añadir `updatedDate` con
   la fecha real de revisión en Madrid; no fingir una nueva publicación.
4. Si cambia la tesis, explicar el matiz y valorar una pieza nueva con editorial-dedup.
5. Aplicar prepublish-check y comunicar secciones cambiadas, evidencia, comandos
   ejecutados y limitaciones. Actualizar la issue si el encargo lo autoriza.

No reprogramar drafts relacionados ni crear automatizaciones recurrentes al invocar
esta skill. No borrar una afirmación histórica sin explicar su contexto cuando siga
siendo necesaria para entender el aprendizaje del artículo.
